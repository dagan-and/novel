# 2005년 사이트 자동화의 범위

조사일 2026-11-18. 당시 가능한 기술과 이야기에서 실제로 구현한 기능은 구분한다.

## 원문 근거

- [RSS 2.0.1 명세](https://www.rssboard.org/rss-2-0-1): 2003-07-15 공개 명세. 외부 소식의 제목·원문 링크·갱신 정보를 수집하는 기반은 2005년 이전에 있었다. 특정 게임 사이트가 당시 RSS를 제공했다는 증거는 아니다.
- [PHP 공식 2004년 발표](https://www.php.net/archive/2004.php): 2004-07-13 PHP 5 출시와 SimpleXML·DOM 등 XML 처리. 실제 선택한 호스팅이 이를 지원했는지는 별도 확인한다.
- [GNU Wget 배포 보관소](https://ftp.gnu.org/gnu/wget/): 1.9.1 파일은 2003년 자료이며 1.10은 2005년 6월 이후다. 4월 계획은 후대 버전을 가져오지 않는다.

이 근거로 웹 수집·피드 처리 자체가 당시 가능했다는 결론을 내릴 수 있다. 예약 실행 가능 여부와 외부 접속·DB·메일·저장 한도는 당시 호스팅 선택 시 확인한다. 서버 예약 실행이 없으면 집 PC의 예약 작업을 대안으로 검토하되 PC가 꺼져도 사이트 전체가 멈추는 구조로 만들지 않는다.

## 초기 조사와 서술의 교정

이전 구성은 1~2월 사이트 구현을 다루면서 수집·데이터 가져오기·예약 운영을 누락했고, 4월에 처음 떠올린 것처럼 서술했다. 사용자가 이 부자연스러움을 지적했다. 개발 경력과 영어 능력을 가진 주인공의 초기 아키텍처에는 이 항목들이 처음부터 들어가는 것이 타당하다.

교정된 흐름은 **1월: 수집/자료 구조·검수·예약 작업 설계와 표본 구현 → 2월: 검증 가능한 자료원의 가져오기·중복 검사·예약 백업 연결 → 3월: 개학 후 자동 처리와 야간 검수 → 4월: 안정화·자료원 확장·실패 감지 개선**이다. 이는 사용자 지적을 반영한 과거 서술 보완 초안이지 기존 기록에서 이미 입증된 완료 이력이라고 주장하지 않는다. 사건 E024~E026과 월별 revision_status를 추적한다. 특정 자료원/호스팅의 역사 검증과 완료 측정은 여전히 별개다.

| 범위 | 무인 실행 가능 | 사람이 할 일 |
| --- | --- | --- |
| 가입·검색·게시글·유틸 계산 | 저장과 결과 생성 | 계정 문제·오류 처리 |
| 새 소식 수집 | 제공되는 RSS나 수집 가능한 페이지의 제목·주소·갱신 감지, 중복 제거 | 당시 자료원·조건 확인, 변경 내용과 버전 검수 |
| 자료 갱신 | 검증된 입력에서 색인·캐시 갱신 | 조합·공략 정확성 판단, 직접 쓴 설명 |
| 운영 | 예약 백업·오류 기록·실패 재시도·관리 요약 | 복원 시험, 심각한 오류·신고·분쟁 대응 |
| 수익 | 광고 게재와 집계의 기반 | 지급 조건·정산·실제 수령 확인 |

처음 설계하는 수집기의 기본 흐름은 수집 → 변경·중복 검사 → 검수 대기 → 사람이 확인 → 게시·색인 갱신이다. 선택한 자료원에서 지원되는 범위만 사용한다. 모든 커뮤니티 본문을 자동 복제하거나 AI처럼 원문을 이해해 공략·답변을 자동 작성하는 것으로 쓰지 않는다.

예정 주기는 6시간마다 새 소식 확인, 야간 1회 백업처럼 작은 범위부터다. 요청량과 저장량은 자료원·호스팅 조건을 보고 정한다. 운영 요약 확인 20~40분은 도입 후 목표 견적이며 실제 기록이 아니다. 필수 운영과 새 기능 개발을 구분하면 야간 4시간 전체를 매일 관리에 쓰지 않고 확장·개선에 사용할 수 있다.


## 필수 선행 조사

앞으로 사이트를 구상할 때는 페이지와 게시판 목록만 만들지 않는다. 자료원과 당시 제공 형식, 가져오기/갱신/검수 경로, 반복 작업, 예약 실행 가능한 환경, 비용·저장·트래픽, 운영자가 직접 판단할 항목까지 함께 확인한다. 가능한 기술을 초기 기획에서 누락한 뒤 뒤늦게 발견한 것처럼 이야기하지 않는다. data/site_architecture.json은 이 구조를 추적하는 제작용 목록이다.
