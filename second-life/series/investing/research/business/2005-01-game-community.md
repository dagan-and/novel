# 2005년 1월 게임 정보·커뮤니티 구축 분석

- 실제 조사일: 2026-11-18
- 대상: 2005년 1월, 만 15세 용식의 소설 속 초기 사업.
- 상태: 사용자 선택과 역사 조사에 따른 사업·일정안. 실제 웹사이트 제작·공개·가입 신청은 하지 않았다.

## 이번에 확정한 방향

사용자는 웹·앱 개발 경력에 더해 **C#·PHP·Java·영어 능숙**을 확인했다. 어머니 명의의 애드센스로 수익을 얻고 **어머니 50%·용식 50%**로 나눈다. 어머니는 계약·정산의 실제 책임 주체, 용식은 개발·콘텐츠·운영을 맡는 설정이다. 계약·소득 귀속·지급 절차는 당시 조건을 확인한다. 분배 전에 비용을 공제하는지는 아직 명시적으로 확정하지 않았으며 아래에 추천 기준을 둔다.

사이트는 **WoW와 디아블로 게임 정보·커뮤니티**로 선택했다. 지금의 인벤·디시에서 이용 구조와 운영 아이디어를 가져온다. 2005년에 공개된 글을 그대로 베끼거나 당시 없던 게임 버전의 데이터를 현재 정보로 섞지 않는다. 현대 서비스 코드를 기억해 자동으로 복원한 것으로 처리하지 않는다. 첫 삶의 해당 게임 플레이 경험은 확인 전이다.

## 첫 버전의 기능

하나의 사이트에서 회원·로그인·검색·관리 기능을 공유하고 WoW와 디아블로 II 영역을 나눈다. 처음에는 WoW 신규 유입 대응을 우선하고 디아블로 정보를 병행한다.

| 영역 | 첫 공개에 포함 | 공개 후 확장 |
| --- | --- | --- |
| 공통 | 회원·글·댓글·공지·검색·신고·관리자·백업 | 북마크·추천 정렬·활동 보상 등 |
| WoW | 초보 안내·직업별 핵심 가이드·퀘스트 질문·자유게시판·파티/길드 모집 | 서버별 공간·제작/아이템 검색·필터·특성 계산 등 |
| 디아블로 II | 1.10 기준 육성 안내·일부 룬 조합·질문 게시판·검색 | 룬/아이템 조건 필터·확장 계산 도구 등 |
| 정보 관리 | 각 글의 게임·적용 패치·확인일 표시, 영문 출처를 읽고 직접 작성한 설명 | 패치 변경 비교·사용자 교정·정보 구조 확장 |

직업×서버별 게시판을 처음부터 모두 나누지 않는다. 글이 적을 때는 공통 게시판에 분류를 붙이고 활동이 생기면 나눈다. 모든 아이템·퀘스트를 초기부터 완성하는 일은 별도 대규모 데이터 작업이다. 첫 공개의 DB는 중요한 항목으로 범위를 제한한다. 반복 이용을 만드는 정확한 정보와 질문 응답이 회원 수보다 앞선 목표다.

## 2005년 개발 방식

AI 코딩·번역·콘텐츠 생성 보조 없이 직접 개발·자료 독해·작성·검증한다. 숙련과 강화된 뇌는 코드 설계와 이해·오류 수정에 도움이 되지만 콘텐츠 입력·패치 검증·실사용 반응·우편을 생략하지 않는다.

초기 예산 약 10만 원에서는 **PHP·MySQL 기반 PC 웹**을 우선 검토한다. C#·Java는 개인 도구나 자료 정리에 쓸 수 있으나 처음부터 서버 환경을 세 가지로 분산하지 않는다. PHP 공식 자료는 PHP 5가 2004-07-13 출시됐음을 확인하며, SIR 공식 연혁은 그누보드가 2003년에 개발됐음을 확인한다. 이는 당시 게시판 기반을 재사용할 수 있었다는 근거이지, 현대 그누보드 버전을 2005년에 쓰라는 의미가 아니다. 실제 채택 버전·라이선스·호스팅 호환성은 선택 때 확인한다. [T01](https://www.php.net/archive/2004.php), [T02](https://sir.kr/about/company)

## 제작 기간 추정

아래는 역사적 통계나 능력치에서 계산한 공식이 아니라 **범위별 작업 견적**이다. 겨울방학 중 하루 약 6시간, 주당 35~45시간을 조사·개발·콘텐츠·운영 준비에 쓰며 기존 게시판 기반을 재사용한다고 가정한다. 수면·식사·학업 시간은 별도 확보한다.

| 단계 | 시작 후 기간 | 결과 |
| --- | --- | --- |
| 기획·당시 환경·계약 준비 | 1~3일 | 이름·구조·최초 콘텐츠·예산과 담당 확정 |
| 회원·게시판 기반·공통 화면 | 4~9일 | 두 게임 공간, 관리자 기능, 기본 동작 |
| 첫 정보·검색·검증·초대 공개 | **10~21일** | 작은 게임 정보·커뮤니티 첫 공개 |
| 핵심 기능·정보 보강 | **4~6주** | 비교적 안정된 초기 운영판. 약 160~240시간 규모 |
| 제한된 아이템/룬/퀘스트 검색 확장 | **6~10주 이상** | 일부 범위의 구조화된 정보. 대형 사이트 전체 DB는 아님 |

1월 1~3일 시작이라면 **1월 중순~하순 첫 공개**, **1월 말~2월 중순 초기 운영판**이 자연스럽다. WoW 1월 18일 상용화에 맞추려면 첫 공개를 1월 15~17일로 목표 삼되 WoW 기본 정보·공통 게시판·디아블로 소규모 안내로 한정한다. 두 게임의 완성 DB와 대형 커뮤니티를 그때 모두 갖췄다고 쓰지 않는다. 전부 자체 개발하면 초기 운영판은 대략 6~10주를 따로 잡고, 자료 범위를 늘리면 더 길어진다. 이 기간도 견적이며 고정 사실이 아니다.

3월 개학 후에는 학교·수면·운영 대응에 맞춰 개발 투입을 다시 정한다. 이후 성장의 병목은 코드 외에도 콘텐츠·검색 유입·사용자 응대·운영비·호스팅 용량이다. 회원 활동이 충분해지는 시점은 개발 완료 날짜에서 계산하지 않는다.

## 광고 승인과 돈이 들어오는 시점

Google 공식 2005-11-14 글은 **Blogger 경유 신청**에서 보통 2~3일 승인을 설명한다. 이는 2005년 1월 한국의 독립 게임 사이트에 대한 보장된 처리 시간이 아니다. [A01](https://adsense.googleblog.com/2005/11/blogging-for-dollars.html)

소설 일정에는 공개할 만한 사이트와 독자적인 정보가 준비된 뒤 신청하고 **약 3~14일의 승인·수정 여유**를 두는 안을 권한다. 이는 작가의 일정 가정이며 당시 공식 심사 기간이 아니다. 재검토가 필요하면 2~4주 이상으로 늘어날 수 있고 승인 자체도 확정 사건이 아니다.

| 구간 | 일정에 넣는 방식 |
| --- | --- |
| 사이트 공개 | 1월 중순~하순 목표. 신청 전에 기능·콘텐츠가 실제 존재해야 함 |
| 승인·광고 노출 | 1월 하순~2월 목표. 실제 승인 전 수익을 생성하지 않음 |
| 지급 기준 달성 | 방문자와 광고 발생액에 따라 달라짐. 정해진 날짜를 보장하지 않음 |
| 주소 확인·지급·수표·현금화 | 우편과 지급 주기·은행 처리 시간을 따로 둠 |

공식 2005-10-04 안내는 PIN 우편이 발송 후 2~4주 걸릴 수 있다고 설명한다. 문서의 발행 시점과 지역 차이를 기록하며 이 기간을 1월의 보장값으로 쓰지 않는다. Google 한국팀은 2009년 지급수단 안내에서 기존 수표 도착에 몇 주가 걸렸다고 설명한다. 따라서 2005년 첫 정산을 현대의 자동 계좌 입금처럼 즉시 처리하지 않는다. 당시 1월의 구체 지급·주소 확인 조건은 확인 과제로 남긴다. [A02](https://adsense.googleblog.com/2005/10/from-inside-adsense-international-mail.html), [A03](https://korea.googleblog.com/2009/08/blog-post_882.html)

1월 하순 광고를 시작해 2월 말까지 당시 지급 조건과 기준액을 모두 충족했다는 **가정**을 택하면 첫 현금 수령은 3~4월을 후보로 둘 수 있다. 이는 월별 지급과 우편·현금화의 여유를 잡은 조건부 일정이며 수익 예측이 아니다. 기준액을 못 채우면 더 늦어진다. 어머니와 용식에게 배분할 현금도 실제 수령 전에는 만들지 않는다.

## 반반 정산

확정: 어머니 50%, 용식 50%. 추천: 실제 입금액에서 해당 기간의 운영비를 한 번 공제한 뒤 남은 금액을 반씩 배분한다. 예를 들어 실제 수령 30만 원·운영비 2만 원이면 잔여 28만 원 중 각 14만 원이다. 이는 세금 정산 전의 단순 예시이며 수입·비용·세금·분배를 구분해 기록한다. 비용을 누가 먼저 부담하는지와 공제 기준은 아직 결정 전이다. 외부 광고 플랫폼의 수익 배분과 가족 간 50:50을 혼동하지 않는다.
