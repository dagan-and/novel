# 자료·최신 상태·이력 분리 구조안

- 작성: 2026-11-18
- 상태: 제안. 이번 작업은 구조 설계이며 기존 파일 이동·삭제, 상태 JSON 형식 변경, 가상 거래 생성은 하지 않았다.
- 범위: 공통 베이스와 투자 편. 다른 작품이나 편의 자산·인물을 섞지 않는다.

## 접근 선택

한 파일에 모두 적으면 시작은 간단하지만 자료·원고·잔액의 기준을 구분하기 어렵다. 모든 내용을 데이터베이스로 옮기는 것은 현재 규모에서 부담이 크다. **설명은 Markdown, 반복되는 수치 이력은 CSV, HTML에 전달할 최신 상태는 JSON**으로 나누는 방식을 추천한다. 설명 문서를 읽으며 진행하는 기존 방식을 유지한다.

## 권장 구조

```text
second-life/
  README.md
  base/                         # 모든 편에 적용하는 설정과 능력
    character.md
    cognition.md
    physiology.md
    nutrition.md
    timeline.md
    abilities.md
    science-references.md
    first-life.md               # 사용자 확인으로 점진 확정하는 첫 삶의 경험
  workflow/
    monthly.md
    storage-design.md           # 이 구조안
  series/investing/
    README.md                   # 현재 작업·다음 행동과 파일 안내
    state.json                  # 진행 위치·기준일·마지막 확정 월·다음 월
    research/
      README.md                 # 자료 목록·출처·검증 상태와 조사 규칙
      2005-korea-market.md       # 기존 조사 출발 문서 보존
      markets/2005-01.md         # 월별 시장·경제 조사
      companies/<company-id>.md # 기업별 장기 참고 자료
      rules/                    # 당시 계좌·세금·거래·생활 제도
      data/                     # 출처·단위·변환 이력이 있는 원시/가공 수치
    characters/
      <person-id>.md             # 편별 인물의 고정 프로필·첫 등장·관련 사건 링크
    ledger/
      transactions.csv          # 초기 자금·거래·수입·지출·이체의 확정 원장
      prices.csv                # 평가일·가격·환율·출처·가격 종류
    current/
      finances.json             # 원장에서 산출한 최신 현금·보유·평가액
      people.json               # 최신 관계·소속 등 변화하는 인물 상태
      life.json                 # 최신 거주·학교·신체 실측 등 생활 상태
    months/
      2005-01.md                # 작업 중 초안과 확정 사건·선택·결과
    snapshots/
      2005-01.json              # 그달 마감 때 고정한 당시 상태
    episodes/
      001.md                    # 소설 본문
    public/                     # 공개 허용된 상태·요약으로 생성한 HTML 등
```

위 트리는 도입할 위치를 나타낸다. 사용 전부터 모든 폴더와 빈 파일을 만들 필요는 없다. 기업·인물·원고는 실제로 필요할 때 추가한다. 공통 첫 삶의 경험은 base에 한 번 기록하고 투자 편에서 링크한다. 편별로 달라진 관계·이력은 그 편에만 기록한다.

## 어느 파일이 기준인가

| 정보 | 수정하는 기준 | 다른 위치의 역할 |
| --- | --- | --- |
| 공통 능력·생일·회귀 규칙 | base의 해당 문서 | 편에서는 링크하며 중복 정의하지 않음 |
| 첫 삶의 경험 | base/first-life.md의 사용자 확인 항목 | 미확정은 별도 표시. 시장 조사 사실을 자동 편입하지 않음 |
| 과거 실제 시장·제도 | research의 출처가 있는 조사 기록 | 원고·월별 판단에서는 해당 자료를 참조 |
| 확정 금전 이동·증권 수량 | ledger/transactions.csv | current/finances.json과 월말 스냅샷은 계산 결과 |
| 평가 가격·환율 | ledger/prices.csv | 현금 이동과 구분. 가격·기준일·출처에 따라 평가액 계산 |
| 편별 인물의 고정 설정 | characters/<person-id>.md | 공통 주인공 프로필은 base를 참조 |
| 인물·생활에서 실제로 생긴 변화 | 확정된 월별 사건 | current의 해당 상태는 사건에서 갱신한 최신 요약 |
| 작업 중 후보·선택 전 상황 | months의 초안 | 확정 원장과 current에 반영하지 않음 |
| 과거 월말 당시 상태 | snapshots/YYYY-MM.json | 이후 달이 진행돼도 해당 월을 최신 상태로 덮어쓰지 않음 |

잔액을 원고·월 문서·최신 JSON에서 각각 손으로 결정하지 않는다. 원장의 초기 자금과 증감을 기준으로 계산하고, 원고의 금액을 계산 결과에 맞춘다. 월 문서에서 사건을 설명하더라도 금액 재계산은 원장을 따른다. 초안의 숫자는 확정 원장과 구분한다.

state.json에 이미 있는 진행 메타데이터는 보존하며, 실제 도입 시 마지막 확정일·current와 스냅샷 위치를 가리키도록 확장한다. 기존 month_end_state와 새 current 양쪽에 독립적인 잔액을 유지하지 않는다. 구체 스키마는 도입 때 정하고 상태가 비어 있으면 null로 둔다. 초기 자금 미정을 0원으로 바꾸지 않는다.

## 날짜·식별자·공개 범위

- current의 ‘최신’은 이야기 속 최신 확정 시점이다. 모든 상태에 이야기 기준일(as_of)을 둔다. 실제 오늘 날짜와 구분한다.
- 연구에는 원래 사건일, 자료 발행·공개일, 실제 조사일, 출처 URL, 확인 상태를 남긴다. 미래에 발행된 자료를 2005년 당일 열람한 자료처럼 쓰지 않는다.
- 2026년까지의 회귀 기억으로 안 내용은 경험 출처를 별도로 남긴다. 당시 공개 자료·첫 삶의 기억·작가의 사후 조사 자료를 구분한다.
- 인물·기업·계좌·거래·사건에 고유 ID를 붙이고 이름은 표시값으로 쓴다. 동명이인·개명·기업명 변경 때 동일 대상을 추적한다.
- 돈에는 통화, 증권에는 종목 식별자·수량, 평가에는 가격 날짜·원시/수정주가 구분·환율을 붙인다. 거래 가격에 수정주가를 잘못 대입하지 않는다.
- 원장은 첫 자금·입출금·거래·수수료·세금·배당·기업행위를 명시하고, 이체를 수익으로 세지 않는다. 동일 거래 ID의 행을 중복 합산하지 않는다. 구체 열 설계는 첫 금융 기록 전에 확정한다.
- 공개용 데이터는 명시적으로 공개 허용한 항목만 내보낸다. research·base·미공개 인물·사용자 개인 경험을 사이트 메뉴에 자동 노출하지 않는다.

## 갱신 순서

1. 진행 시점과 직전 확정 상태를 읽는다.
2. 필요한 자료를 research에 조사하고, 사용자 기억을 확인해 첫 삶의 경험에 반영한다.
3. 선택과 장면을 months의 초안에서 진행한다.
4. 사건이 확정되면 월 문서에 확정 표시하고 금전·수량 변화를 원장에 기록한다. 인물·생활 변화의 근거 사건도 기록한다.
5. 원장을 계산하고 해당 사건을 반영해 current와 진행 메타데이터를 같은 기준일로 맞춘다. 중간 장면 단위로 확정할 수 있다.
6. 월 마감 시 해당 월의 스냅샷을 저장하고 공개 요약을 확정한다. 이후 기록을 수정해야 하면 사유와 영향을 남기고 종속 요약을 함께 재생성한다.
7. 공개 허용된 요약·상태에서 HTML을 생성한다. 로컬 생성과 커밋·푸시·배포는 각각 구분한다.

도입 순서는 first-life 기록과 연구 안내 → 최초 자금·인물의 스키마 → 원장과 current → 첫 월말 스냅샷이다. 잔액·보유량·평가액 계산 자동화는 금융 스키마를 확정한 뒤 추가한다. 현재 확정 사건·자산이 없는 상태를 그대로 보존하며 기존 파일은 실제 이전 필요가 확인될 때만 이동한다.
