# 세계관 탐색과 연속성 관리

## 읽기와 이어가기

1. 프로젝트 README와 해당 편 RESUME에서 현재 시점·마지막 작업·다음 행동을 확인한다.
2. `base/`에서 이번 작업에 필요한 설정만 읽고 해당 편 `data/records.json`, `state.json`, 작업 월 `months/YYYY-MM.md`를 확인한다.
3. 역사 검증이 필요한 내용만 `research/`에서 확인하고 부족하면 조사한다. 다른 작품이나 편의 상태를 가져오지 않는다.
4. 사용자 메시지가 새 설정, 변경, 진행 요청 중 무엇인지 판단하고 기존 ID와 대조한다. 동일 정보를 새 사건으로 중복 생성하지 않는다.

## 파일별 기준

| 정보 | 기준 위치 | 규칙 |
| --- | --- | --- |
| 생일·능력·기억·첫 삶 경험 | base의 해당 문서 | records에는 위치만 참조. 수치를 이중 관리하지 않음 |
| 사용자 확정 선택·이야기 사건·미결 질문·할 일 | 편별 data/records.json | ID, 상태, 날짜, 근거, 관련 파일을 기록 |
| 월간 탐색 서술 | months/YYYY-MM.md | 용식의 1인칭. 대화·독백 없음. 확정/초안은 머리말에서 표시 |
| 작업량·일정·구현 상세 | planning/ | 탐색 본문에서 분리. 과거 계획은 실적이 아님 |
| 검증한 시대 정보 | research/ | 역사적 사실과 창작 사건을 구분 |
| 마지막 확정 월·진행 위치 | state.json | 초안 게시로 변경하지 않음 |
| 확정 금전 이동 | ledger/ 도입 후 원장 | 거래 전에는 원장을 만들며 가짜 잔액을 채우지 않음 |
| 다음 세션 인계 | RESUME.md | 상태 요약·미결·다음 행동을 기록하고 근거 ID 연결 |
| 공개 HTML | index.html | scripts/render_investing.py로 월 본문에서 생성 |

## 상태의 의미

- `confirmed`: 사용자가 명시적으로 선택한 설정·방향 또는 명시 확정한 이야기 사건.
- `draft`: 작가가 구성한 선택·사건·결과. 읽을 수 있는 이야기로 작성할 수 있으나 확정 원장이나 월말 상태에는 반영하지 않는다.
- 작업 상태는 `planned`, `in_progress`, `done`, `blocked`. 이야기 속 사이트 구축 작업과 실제 저장소의 HTML 수정 작업을 혼동하지 않는다.
- 실제 작업시간은 수행 기록이 있어야 입력한다. 예상 시간으로 actual_hours를 채우지 않는다. 할 일 완료율 역시 근거 없이 만들지 않는다.
- `unknown`은 아직 정하지 않은 항목이다. 선택지를 되묻기 전에 기존 기록에 답이 있는지 확인한다.

초안 사건을 확정할 때 사용자 승인이 기존 요청에 포함되는지 먼저 판단한다. 새로 만든 매출·거래·공개·월말 잔액을 사용자 확정으로 가장하지 않는다. 초안 작성에 매번 승인을 요구하지는 않는다.

## 변경과 충돌

사용자의 최신 지시가 우선한다. 바뀐 결정을 records의 `changes`에 날짜·대상·사유와 함께 적고 이전 설명은 역사로 취급한다. 공통 설정 자체를 바꾸면 base부터 고친다. 기록끼리 충돌하면 최신 사용자 지시 → 공통 base → 확정 기록 → 초안 순서로 정리하되, 같은 단계에서 해소되지 않으면 해당 항목을 보류하고 필요한 질문만 한다.

작성 뒤 ID·참조 경로·작업 의존성·미정 값·월 상태를 `python3 scripts/check_continuity.py`로 점검한다. 이는 구조 오류 점검이며 글의 의미상 모순이나 역사 검증을 대신하지 않는다. 서술과 사건 목록을 사람이 읽듯 함께 대조한다.

## 서술의 밀도

각 달은 배경과 현재 조건 → 내가 발견한 변화 → 선택의 근거 → 실행 중 확인한 것 → 월말에 달라진 점과 다음 문제로 이어진다. 기능 이름을 나열하는 대신 그 기능을 직접 다루었을 때 무엇이 가능해졌는지 설명한다. 능력은 단순 찬사가 아니라 이해·연결·판단·실행에서 관찰되는 차이로 표현한다. 미래 기억·강화된 뇌·새로 조사해 얻은 정보는 서로 구분한다.

## 활동의 지속

records의 ongoing_threads는 현재 이어지는 활동의 목록이다. 새 달을 쓸 때 각 활동이 계속·변경·종료되는지를 먼저 검토한다. 새 주제의 질문은 기존 본줄기에 더해지는 것으로 해석한다. 기능 개발과 운영이 병행되는 사업은 공개 이후에도 자료 보강·응대·오류 수정이 자연스럽게 이어지도록 서술한다. 완료되지 않은 작업은 이월하고, 초안 사건과 실제 완료 상태를 구별한다.


## 지표와 현황판

반복 수치는 투자 편 data/metrics.json에 저장한다. 월별 유입·광고 발생액을 입력한 뒤 refresh_metrics.py로 누적·일평균·일별 모형 배분을 계산하고 check_continuity.py로 대조한다. render_investing.py는 월간 서술과 dashboard.html을 함께 만든다. 3월 원본 수익 시나리오와 4월 원본 체격은 source_links에서 읽어 반영하므로 독립적인 사본으로 수정하지 않는다. 새 월의 지표가 없으면 누락을 해결하거나 미정 null을 명시한다. 숫자 정밀도가 출처의 정확도를 뜻하지 않는다. 미래 월의 성적·평판을 과거 월에 노출하지 않는다. 관계 변화는 정성적으로 관리한다. 비용·세금·환율·정산 미정에서는 순이익과 현금잔액을 생성하지 않는다.
