# 워크플로우

## 현재 상태

- 이 폴더는 장기 연재 중인 연속 서사 프로젝트다.
- 설정 보강 요청과 원고 진행 요청을 구분해서 처리한다.
- 설정 보강 요청에서는 화별 개요와 시나리오를 새로 작성하지 않는다.
- 기존 프로젝트의 고유명사, 사건, 루프 구조는 이 프로젝트의 기본값으로 사용하지 않는다.

## 플러그인·스킬 활용 원칙

- Creative Production은 소설 장면의 감정선, 관계 긴장, 삽화 후보 장면의 연출 의도를 보강할 때 사용한다. 원고 자체의 확정 설정을 새로 만들기보다 기존 상태와 연대기를 바탕으로 장면의 맛을 세우는 보조 역할로 둔다.
- Product Design은 실사풍 캐릭터 기준 이미지, 회차 삽화의 구도·조명·의상·표정 가이드, 표지나 홍보용 비주얼 방향을 잡을 때 사용한다. 실제 원고 사건을 바꾸는 용도로 사용하지 않는다.
- Superpowers는 새 기능 추가, 워크플로우 변경, 큰 설정 정리, 검토·디버깅처럼 절차 관리가 필요한 작업에 사용한다. 소설 본문을 쓸 때는 창작 흐름을 방해하지 않는 범위에서 계획과 점검에만 활용한다.
- imagegen은 실제 이미지 생성·편집을 맡는 기본 도구로 본다. 회차 삽화나 캐릭터 기준 이미지가 프로젝트에 쓰이면 생성 후 반드시 작업 폴더 안의 정해진 경로로 저장한다.
- 플러그인은 원고와 설정의 보조 도구일 뿐이다. 최종 판단 기준은 `AGENTS.md`, 상태 파일, 연대기, 각 설정 문서에 기록된 프로젝트 규칙이다.

## 요청별 처리

### "세팅 정리해줘" / "설정 구축해줘"

1. `AGENTS.md` 확인
2. `planning/` 문서 확인
3. 문체/읽힘 변경이 있으면 `setting/문체규칙.md` 확인
4. 개요 구조 변경이 있으면 `setting/개요작성규칙.md` 확인
5. 원고 작성 규칙 변경이 있으면 `setting/시나리오작성규칙.md` 확인
6. 정보 접근·시점 관리 변경이 있으면 `setting/정보접근잠금규칙.md` 확인
7. 삽화 자동화 변경이 있으면 `setting/삽화생성규칙.md` 확인
8. 욕망, 질투, 양다리, 관계 서스펜스 변경이 있으면 `setting/욕망관계서스펜스규칙.md` 확인
9. 성인 장면 운영 변경이 있으면 `setting/성인장면처리규칙.md` 확인
10. 필요한 설정 문서만 수정
11. 원고 생성 금지

### "캐릭터 세팅해줘"

1. `planning/캐릭터운영원칙.md` 확인
2. `characters/캐릭터양식.md` 확인
3. 해당 캐릭터 파일 작성 또는 수정
4. `관계망.md`에는 확정된 초기 관계만 반영
5. 원고 생성 금지

### "소설 시작해줘"

1. `setting/원고진행핵심체크.md`
2. `planning/시리즈개요.md`
3. `planning/핵심컨셉.md`
4. `setting/개요작성규칙.md`
5. `setting/문체규칙.md`
6. `setting/시나리오작성규칙.md`
7. `setting/정보접근잠금규칙.md`
8. `관계망.md`
9. `연대기.md`
10. 관계 서스펜스나 욕망 장면이 필요할 경우 `setting/욕망관계서스펜스규칙.md`
11. 성인 장면 처리가 필요할 경우 `setting/성인장면처리규칙.md`

이 순서로 읽은 뒤, 먼저 다음 5화 개요안을 제시하고 사용자 확인을 받는다.

### "소설 진행해줘"

- 사용자 확인 없이 자동 진행하는 요청으로 취급한다.
- 단, 장기간 공백 뒤 진행하거나 큰 설정 변경 직후 진행할 때는 먼저 현재 세팅이 충분한지 점검한다.
- 원고 작성 전에 `setting/원고진행핵심체크.md`를 먼저 확인한다.
- 원고 작성 전에 `setting/정보접근잠금규칙.md`에 따라 이번 화 또는 묶음의 정보 접근 잠금표를 내부 기준으로 작성한다. 특히 각 인물의 `아는 것`, `모르는 것`, `절대 들키면 안 되는 정보`, `대사에 나오면 안 되는 금지 단어/이름/지명`을 먼저 잠근다.
- 정보 접근 잠금표는 반드시 `states/knowledge_state.json`의 최신 캐릭터별 지식 상태를 기준으로 만든다.
- 원고 작성 전에 개요, 상태 파일, 연대기, 캐릭터 고정 정보에 없는 새 사실을 만들지 않는다는 점을 확인한다. 필요한 새 사실이 있으면 본문에서 확정하지 말고 사용자 개요나 설정 보강 대상으로 분리한다.
- 장면 감정선이나 삽화 연출 방향이 흐릿하면 Creative Production 관점으로 장면 목적, 관계 압력, 독자가 보게 될 순간을 먼저 정리한다.
- 원고 작성 직후 `setting/원고검토훅.md`에 따라 설정붕괴, 캐릭터 붕괴, 호칭, 시간 흐름, 정보 접근, 문체, 화말 훅을 필수 검토한다.
- 원고 작성, 원고 검토 훅 통과, 기록 업데이트를 먼저 완료한다.
- 각 화마다 완성 원고 기준 삽화 후보 장면 1~3개와 짧은 생성 메모를 작업 결과에 남긴다. 이 단계에서는 imagegen을 호출하지 않고, 에피소드 Markdown에 이미지 링크도 삽입하지 않는다.
- 원고와 기록만으로 완결된 상태에서 최종 HTML 변환과 `wish-real` 폴더 푸시까지 자동 실행한다.
- 사용자가 "삽화 작업", "삽화 일괄 생성", "이미지 붙여줘"처럼 별도 요청하면 `setting/삽화생성규칙.md`에 따라 후보 메모와 최종 원고를 바탕으로 묶음 단위 삽화를 생성·저장·삽입하고 HTML 변환과 푸시를 다시 실행한다.

## 파일 저장 규칙

- 일반 에피소드: `episodes/[001-100|101-200|201-300]/ep.[번호].md`
- 성인 장면이 포함되어도 일반 에피소드 파일명 `episodes/[001-100|101-200|201-300]/ep.[번호].md`를 사용한다.
- 삽화 이미지: `images/ep[3자리 번호]/scene-[2자리 번호].png`
- 성인 장면 여부로 파일명을 따로 구분하지 않고, 원고 하단에 별도 성인씬 기록 블록도 만들지 않는다. 필요한 관계 진도와 후폭풍은 본문 흐름, `states/current_state.json`, `연대기.md`에만 반영한다.
- 시나리오 작성 요청 전에는 `episodes/`에 파일을 만들지 않는다.

## 소설 진행 자동 사이클

1. 현재 상태와 연대기를 확인한다.
2. `setting/원고진행핵심체크.md`를 확인한다.
3. `states/knowledge_state.json`을 확인해 캐릭터별 지식 상태와 금지 대사 정보를 잠근다.
4. 필요한 설정 문서를 읽는다.
5. 고정 사실 잠금 항목을 확인한다.
   - 학력, 나이, 재수 여부, 가족사, 과거 연애, 큰돈 거래, 투자 결과, 복권 정보, 관계 단계, 정보 접근은 개요·상태 파일·연대기·캐릭터 고정 정보에 있는 내용만 사용한다.
   - 새 사실처럼 보이는 문장이 필요하면 확정 과거가 아니라 감정, 분위기, 추측, 말하지 못한 생각으로 처리한다.
6. `setting/정보접근잠금규칙.md`의 정보 접근 잠금표를 내부 기준으로 작성한다.
   - 등장 인물별 `아는 것/모르는 것`을 분리한다.
   - 이번 화에서 새로 들켜도 되는 정보와 절대 들키면 안 되는 정보를 분리한다.
   - 대사에 직접 나오면 안 되는 이름, 지명, 관계 진실, 날짜, 숫자를 금지어로 둔다.
7. 다음 화 원고를 작성한다.
8. `setting/원고검토훅.md`에 따라 원고 자체를 먼저 검토한다.
   - 화당 3,000자 이상인지 확인한다.
   - 세계관 설정, 캐릭터 성격, 호칭, 말투, 시간 흐름, 정보 접근을 확인한다.
   - 설정 파일에 없는 새 과거사, 학력, 재수 여부, 가족사, 과거 연애, 큰돈 거래, 투자 결과, 정보 접근이 추가되지 않았는지 확인한다.
   - 각 대사의 고유명사, 지명, 이름, 관계명, 날짜, 숫자가 화자의 정보 접근 잠금표와 맞는지 확인한다.
   - 문체, 대사/지문 비중, 장면 목적, 화말 훅을 확인한다.
   - 회귀·미래 지식이 원고 표면에 드러나는 문장과 금지 표현을 검색해 제거한다.
   - 돈을 쓴 장면의 금액과 관계 흔적이 맞는지 확인한다.
   - 잠금표의 금지 단어는 `rg` 또는 `python3 tools/check_knowledge_leaks.py [원고파일...] --knowledge-state states/knowledge_state.json`로 검사한다.
9. 충돌이나 붕괴가 발견되면 원고를 수정하고 8번 검토를 다시 수행한다.
10. 원고 묶음 단위가 끝나면 기록을 업데이트한다.
   - `states/current_state.json`
   - `states/knowledge_state.json`
   - `states/finance_state.json`
   - `연대기.md`
   - 필요한 경우 `관계망.md`
11. 기록 업데이트 뒤에도 원고와 기록 사이에 새 충돌이 생기지 않았는지 `setting/원고검토훅.md` 기준으로 묶음 전체를 한 번 더 확인한다.
12. 삽화 없이도 원고와 기록이 완결된 상태인지 확인한다.
13. 완성 원고에서 각 화별 삽화 후보 장면 1~3개를 추린다.
14. 후보별로 장면 위치, 등장인물, 감정 압력, 시각 소품, 기준 이미지 필요 여부를 짧게 메모한다.
15. 이 단계에서는 imagegen 호출, 이미지 저장, Markdown 이미지 링크 삽입을 하지 않는다.
16. 원고와 기록, 삽화 후보 메모를 최종 확인한다.
17. 작성한 화수를 대상으로 `python3 convert_html.py [화수...]`를 실행한다.
18. `python3 push_wish_real.py -m "Add wish-real episodes [범위]"`를 실행해 `wish-real` 폴더의 모든 변경사항을 스테이징, 커밋, 푸시한다.
19. 17~18단계까지 성공해야 소설 진행 작업 완료로 보고한다.

## 삽화 일괄 작업 사이클

사용자가 별도로 삽화 생성이나 이미지 삽입을 요청했을 때만 실행한다.

1. 대상 화수의 최종 원고와 원고 진행 때 남긴 삽화 후보 메모를 확인한다.
2. 후보가 부족하거나 원고와 어긋나면 최종 원고에서 후보 장면을 다시 고른다.
3. Creative Production 관점으로 후보 장면의 감정 온도, 관계 변화, 화말 훅과의 연결을 점검한다.
4. 실제 삽화 장면을 화당 기본 1장, 필요 시 2장까지 선정한다.
5. Product Design 관점으로 선정 장면의 실사풍 구도, 조명, 의상, 표정, 캐릭터 기준 이미지 반영 요소를 정리한다.
6. imagegen으로 삽화를 생성한다.
7. 이미지를 `images/epNNN/`에 저장한다.
8. 에피소드 Markdown에 이미지 링크를 삽입한다.
9. 원고, 이미지 경로, 기준 이미지 반영 여부를 최종 확인한다.
10. 대상 화수를 다시 HTML로 변환하고 `wish-real` 폴더 변경사항을 커밋·푸시한다.

## 소설 진행 후 마무리 자동화

- 소설을 새로 작성하거나 이어 쓴 뒤에는 `finish_novel_cycle.py`를 사용할 수 있다.
- 예: `python3 finish_novel_cycle.py 11 12 13 -m "Add wish-real episodes 11-13"`
- 원고만 진행한 경우에는 이미지 링크가 없어도 지정 화수 HTML 변환을 먼저 실행한 뒤, 성공한 경우에만 `push_wish_real.py`를 실행한다.
- 삽화 일괄 작업 이후에는 이미지 링크 삽입까지 끝난 최종 원고를 대상으로 같은 마무리 자동화를 다시 실행한다.
- 화수를 생략하면 전체 에피소드를 HTML로 다시 변환한 뒤 푸시한다.
- 원고 작성이 아닌 설정만 수정한 경우에는 이 자동 사이클을 강제하지 않는다.

## 기록 업데이트

- 원고 5화 작성 후에만 `states/current_state.json`, `관계망.md`, `연대기.md`를 일괄 업데이트한다.
- 단, 차량, 고가 선물, 학원·유학, 여행·숙박 예약, 투자처럼 큰돈을 쓰거나 자산이 변하는 장면은 5화 묶음을 기다리지 않고 해당 화 작성 직후 `states/finance_state.json`에 반영한다. 소액 생활비와 일반 데이트 비용은 반영하지 않는다.
- 설정 변경과 원고 진행 기록을 섞지 않는다.
