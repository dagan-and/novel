# 워크플로우

## 현재 상태

- 이 폴더는 30화까지 진행된 연속 서사 프로젝트다.
- 설정 보강 요청과 원고 진행 요청을 구분해서 처리한다.
- 설정 보강 요청에서는 화별 개요와 시나리오를 새로 작성하지 않는다.
- 기존 프로젝트의 고유명사, 사건, 루프 구조는 이 프로젝트의 기본값으로 사용하지 않는다.

## 요청별 처리

### "세팅 정리해줘" / "설정 구축해줘"

1. `AGENTS.md` 확인
2. `planning/` 문서 확인
3. 문체/읽힘 변경이 있으면 `setting/문체규칙.md` 확인
4. 개요 구조 변경이 있으면 `setting/개요작성규칙.md` 확인
5. 원고 작성 규칙 변경이 있으면 `setting/시나리오작성규칙.md` 확인
6. 삽화 자동화 변경이 있으면 `setting/삽화생성규칙.md` 확인
7. 욕망, 질투, 양다리, 관계 서스펜스 변경이 있으면 `setting/욕망관계서스펜스규칙.md` 확인
8. 성인 장면 운영 변경이 있으면 `setting/성인장면처리규칙.md` 확인
9. 필요한 설정 문서만 수정
10. 원고 생성 금지

### "캐릭터 세팅해줘"

1. `planning/캐릭터운영원칙.md` 확인
2. `characters/캐릭터양식.md` 확인
3. 해당 캐릭터 파일 작성 또는 수정
4. `관계망.md`에는 확정된 초기 관계만 반영
5. 원고 생성 금지

### "소설 시작해줘"

1. `planning/시리즈개요.md`
2. `planning/핵심컨셉.md`
3. `setting/개요작성규칙.md`
4. `setting/문체규칙.md`
5. `setting/시나리오작성규칙.md`
6. `setting/삽화생성규칙.md`
7. 관계 서스펜스나 욕망 장면이 필요할 경우 `setting/욕망관계서스펜스규칙.md`
8. 성인 장면 처리가 필요할 경우 `setting/성인장면처리규칙.md`
9. `관계망.md`
10. `연대기.md`

이 순서로 읽은 뒤, 먼저 다음 5화 개요안을 제시하고 사용자 확인을 받는다.

### "소설 진행해줘"

- 사용자 확인 없이 자동 진행하는 요청으로 취급한다.
- 단, 장기간 공백 뒤 진행하거나 큰 설정 변경 직후 진행할 때는 먼저 현재 세팅이 충분한지 점검한다.
- 원고 작성, 원고 자체 검토, 기록 업데이트를 먼저 완료한 뒤 `setting/삽화생성규칙.md`에 따라 한 화당 삽화 1~2장을 마지막 단계에서 생성한다.
- 생성 이미지는 `images/epNNN/scene-XX.png`에 저장한다.
- 에피소드 Markdown에는 저장된 이미지 상대경로를 자동 삽입한다.
- 삽화 생성이 도구 제한으로 실패하면 원고는 저장하되, 실패한 삽화 위치와 프롬프트를 작업 결과에 보고한다.
- 이미지 링크 삽입 뒤 최종 HTML 변환과 `wish-real` 폴더 푸시까지 자동 실행한다.

## 파일 저장 규칙

- 일반 에피소드: `episodes/[001-100|101-200|201-300]/ep.[번호].md`
- 성인씬 컨텍스트 포함 에피소드: `episodes/[001-100|101-200|201-300]/ep.[번호]_a.md`
- 삽화 이미지: `images/ep[3자리 번호]/scene-[2자리 번호].png`
- 같은 번호의 일반 파일과 `_a` 파일을 동시에 만들지 않는다.
- 시나리오 작성 요청 전에는 `episodes/`에 파일을 만들지 않는다.

## 소설 진행 자동 사이클

1. 현재 상태와 연대기를 확인한다.
2. 필요한 설정 문서를 읽는다.
3. 다음 화 원고를 작성한다.
4. 원고 자체를 먼저 검토한다.
   - 화당 3,000자 이상인지 확인한다.
   - 문체, 대사/지문 비중, 장면 목적, 화말 훅을 확인한다.
   - 회귀·미래 지식이 원고 표면에 드러나는 문장과 금지 표현을 검색해 제거한다.
   - 돈을 쓴 장면의 금액과 관계 흔적이 맞는지 확인한다.
5. 원고 묶음 단위가 끝나면 기록을 업데이트한다.
   - `states/current_state.json`
   - `states/finance_state.json`
   - `연대기.md`
   - 필요한 경우 `관계망.md`
6. 삽화 없이도 원고와 기록이 완결된 상태인지 확인한다.
7. 완성 원고에서 삽화 후보 장면을 3~5개 추린다.
8. 실제 삽화 장면 1~2개를 선정한다.
9. 이미지 생성 도구로 삽화를 생성한다.
10. 이미지를 `images/epNNN/`에 저장한다.
11. 에피소드 Markdown에 이미지 링크를 삽입한다.
12. 원고, 기록, 이미지 경로를 최종 확인한다.
13. 작성한 화수를 대상으로 `python3 convert_html.py [화수...]`를 실행한다.
14. `python3 push_wish_real.py -m "Add wish-real episodes [범위]"`를 실행해 `wish-real` 폴더의 모든 변경사항을 스테이징, 커밋, 푸시한다.
15. 13~14단계까지 성공해야 소설 진행 작업 완료로 보고한다.

## 소설 진행 후 마무리 자동화

- 소설을 새로 작성하거나 이어 쓴 뒤에는 `finish_novel_cycle.py`를 사용할 수 있다.
- 예: `python3 finish_novel_cycle.py 11 12 13 -m "Add wish-real episodes 11-13"`
- 이 스크립트는 이미지 링크 삽입까지 끝난 최종 원고를 대상으로 지정 화수 HTML 변환을 먼저 실행한 뒤, 성공한 경우에만 `push_wish_real.py`를 실행한다.
- 화수를 생략하면 전체 에피소드를 HTML로 다시 변환한 뒤 푸시한다.
- 원고 작성이 아닌 설정만 수정한 경우에는 이 자동 사이클을 강제하지 않는다.

## 기록 업데이트

- 원고 5화 작성 후에만 `states/current_state.json`, `관계망.md`, `연대기.md`를 일괄 업데이트한다.
- 단, 돈을 쓰거나 자산이 변하는 장면은 5화 묶음을 기다리지 않고 해당 화 작성 직후 `states/finance_state.json`에 즉시 반영한다.
- 설정 변경과 원고 진행 기록을 섞지 않는다.
