# wish-real 프로젝트 뼈대 설계

## 배경 및 목적

- `wish-short`(단편, 대사 금지, 매화 독립완결)와 `reunion-reboot`(장편 연재, 대사 허용, 라노벨체)의 중간 지점에 있는 새 프로젝트.
- 목표: 대사를 전면 허용하면서도 문장을 압축해 토큰 소모를 줄이고, 화마다 리셋되지 않고 이어지는 연속 서사를 쓴다.
- 세계관·인물 설정은 이 설계에 포함하지 않는다. 구조 확정 후 별도로 브레인스토밍한다.
- `dual_life`, `wish-short`, `reunion-reboot`와는 완전히 다른 세계관/인물을 새로 만든다. 회귀·타임루프 같은 하이 컨셉은 쓰지 않는다.

## 비목표 (Non-goals)

- 세계관, 주인공 설정, 히로인 구성 — 이번 설계에서 다루지 않음
- 실제 노골적 성적 묘사 본문 작성 — AI는 어떤 경우에도 이를 직접 쓰지 않음 (아래 "성인 장면 처리" 참조)

## 정보 소유권 규칙 (핵심 설계 결정)

wish-short는 가변 정보(관계 단계, 최근 변화, 다음 압력, 성인씬 횟수)를 `characters/[이름].md` 안에 직접 적었다. `wish-real`은 이 방식을 쓰지 않는다.

- **고정 정보** (외형·성격·배경·말투 등 거의 안 바뀌는 값) → `characters/[이름].md`에만 기록
- **가변 정보** (관계 단계, 최근 변화, 다음 압력, 성인씬 누적 횟수, 인게임 날짜, 현재 화수) → `states/current_state.json` 한 곳에만 기록
- 같은 정보를 두 파일에 중복 기록하지 않는다. 이는 한쪽만 갱신되어 정보가 어긋나는 사고를 원천 차단하기 위함이다.
- 신규 세션에서 화를 이어 쓸 때, `characters/` 파일은 (신규 히로인이 처음 등장하는 경우가 아니면) 열지 않아도 된다. `states/current_state.json`과 `연대기.md`만으로 맥락을 파악한다.

### `states/current_state.json` 스키마

```json
{
  "current_episode": 0,
  "in_story_date": "",
  "protagonist": {
    "name": "",
    "status": ""
  },
  "heroines": {
    "히로인이름": {
      "stage": "",
      "recent_change": "",
      "next_pressure": "",
      "adult_scene_count": 0
    }
  },
  "last_updated_episode": 0
}
```

### `states/recent_topics.json` 스키마

```json
{
  "recent_topics": [
    { "episode": 0, "topic": "" }
  ]
}
```

- 최근 20화 정도의 소재만 유지하고 그 이전 항목은 정리한다 (소재 반복 방지 목적).

## 화 형식

- **분량**: 화당 3,000~5,000자 (reunion-reboot 수준)
- **대사**: 전면 허용
- **문체**: 라노벨풍으로 문장을 짧게 압축. 서술이 늘어지지 않게 한다.
- **연속성**: 에피소드 번호가 곧 서사 순서다 (wish-short와 달리 정렬용 ID가 아니라 실제 진행 순서). 이전 화 사건은 다음 화의 확정 과거로 자동 연결된다.

## 성인 장면 처리 규칙

- AI는 어떤 프로젝트에서든 노골적인 성적 행위 묘사 본문을 직접 쓰지 않는다. 이는 스타일 문제가 아니라 지켜야 하는 경계다.
- wish-short처럼 무겁고 구조화된 별도 컨텍스트 블록(장소/의상/표정/손·시선 포인트 등 풀 템플릿)은 쓰지 않는다.
- 대신 장면 흐름(로맨틱한 긴장, 스킨십 직전까지)은 대사 포함해서 자연스럽게 서술하고, 실제 노골적인 지점에 도달하면 한두 줄짜리 가벼운 상황 메모로 페이드 처리한 뒤 장면을 마무리한다.
- 이 규칙은 `setting/성인장면처리규칙.md`에 구체 포맷과 예시로 명시한다.

## 워크플로우 (초안)

1. **세션 시작**: `AGENTS.md` → `states/current_state.json` → `연대기.md` 순으로 읽는다.
2. **화 작성 요청 시**: `setting/문체규칙.md`, 관련 히로인 `characters/[이름].md`(고정 정보 필요할 때만) 참고해서 작성한다.
3. **작성 완료 후**: `states/current_state.json`과 `states/recent_topics.json`을 갱신한다 (wish-short STEP 7과 동일한 역할, 대상 파일만 다름).
