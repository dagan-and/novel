# CLAUDE.md — 세계관 + 작성 가이드

-----

## 세계관 설정

### 루프 구조

- 주인공 이름: 시안
- 0차 삶: 38살까지 살다 2008년 20살로 귀환
- 루프: 20살~35살 활동 후 잠들어 20살로 귀환 반복
- 루프 기간: 2008년~2023년 (15년 단위)
- 38년치 기억 완전 보유, 루프마다 누적
- 인물 상세 정보는 시안.md 참조

### 픽업 원칙

- 치트 능력 없음
- 0차 38년 경험과 루프 경험으로 여성 유형 즉시 파악
- 시안은 항상 주도권 유지
- 모든 여성은 결국 시안에게 빠짐
- 난공불락 캐릭터 없음
- 시안이 휘둘리는 관계 없음
- 접근 방식과 전개는 AI 자율

### 호칭 규칙

- 여성의 시안 호칭은 관계 흐름에 따라 AI가 자율 변경
- 변경 기준: 감정적으로 중요한 장면 직후, 또는 전반적으로 관계가 한 단계 깊어졌다고 판단될 때
- 한 번 바뀐 호칭은 이전으로 돌아가지 않음
- 호칭이 바뀐 경우 캐릭터 파일 [수정] 항목에 변경 사항 기록
- 시안이 여성을 부를 때: 성 빼고 이름만 (박미현 → 미현)

-----

## 하렘 시스템

- 동시 유지 인원: 최대 9명
- **메인 5명**: 시안과 깊은 관계를 유지하는 핵심 멤버
- **서브 4명**: 관계는 유지되나 거리가 생긴 멤버 / 신규 진입 대기
- 결혼은 없음 — 하렘 내 모든 여성은 시안과의 관계를 유지

### 메인 → 서브

- 커리어 / 유학 / 개인적 사정 / 심리적 거리감 등으로 자연스럽게 이동
- 시안이 먼저 밀어내지 않음 — 상황과 감정의 흐름으로만 발생

### 서브 → 메인 승격

- 서브 멤버에게 승격 기회 부여 가능
- 승격 조건: 재접근 계기 / 감정선 재점화 / 사건을 통한 관계 재정립
- 승격 여부는 AI가 흐름에 따라 판단

### 하렘 내부

- 멤버들은 서로의 존재를 인지할 수 있음
- 질투 / 경쟁 / 동맹 / 서브 멤버의 승격 시도 등 감정 반응은 AI 자율
- 외부 위협 (경쟁 남성 / 전 남친 / 가족 압박) 활용 가능
- 루프를 넘어 재등장 가능한 멤버는 AI가 판단해 설계

## 성인씬 구역 시스템

> AI는 씬 컨텍스트만 구성한다. 묘사는 작가가 직접 작성한다.

### 트리거 조건

시나리오 흐름상 성적 긴장감이 임계점에 도달했을 때, AI는 묘사 없이 아래 형식의 구역만 삽입한다.

### 구역 포맷

```
---
## [성인씬 #번호 — ep.번호]

- 장소:
- 등장인물:
  - 시안: (현재 감정/상태)
  - [이름]: (현재 감정/상태)
    - 외형 참고: 캐릭터 파일 외형 설정을 읽고 수치 대신 관용적 표현으로 자세히 서술
    - 성격 참고: 성격 키워드 / 감정 표현 방식 / 시안 앞에서의 반응 패턴
- 의상:
  - 시안: (씬 진입 시점 착용 의상)
  - [이름]: (씬 진입 시점 착용 의상)
- 직전 맥락: (이 씬 직전에 어떤 일이 있었는지 한 줄)
- 관계 단계: (현재 친밀도 기준 이 씬의 의미)
- 분위기 키워드: (예: 지배적 / 긴장 / 애절 / 장난스러운)
- 소품 / 환경: (조명, 공간 특이사항 등)
- 씬 이후 감정 방향: (이 씬이 끝난 뒤 관계가 어떻게 변화할지)
- <progress>[단계]</progress>

---
```

### 운영 규칙

- AI는 구역 내부에 묘사를 절대 작성하지 않는다
- 씬 이후 감정 방향은 다음 장면 연결을 위한 참고값
- 시안과 상대 캐릭터의 착용 의상은 에피소드 흐름에서 파악해 구역에 반영
- `<progress>` 태그는 구역 말미에만 기재

## 신규 캐릭터 규칙

- 스토리 진행 중 하렘에 새 캐릭터가 필요한 경우, 반드시 `character_template.md` 기준으로 캐릭터 파일을 먼저 생성한 뒤 등장시킨다
- 파일 없이 이름만 임의로 만들어 사용하는 것은 금지
- STEP 1 개요 단계에서 신규 캐릭터 투입이 예정된 경우, 개요 출력 후 시나리오 작성 전에 캐릭터 생성을 먼저 요청한다

```
신규 캐릭터 생성 프롬프트 (복붙용):

첨부:
- character_template.md
- 시안.md          (시안 설정 참조용)
- RELATION.md      (기존 멤버와 중복 방지 참조용)

신규 [메인 / 서브] 캐릭터를 생성해줘
- 배경 / 직업군: [작가 지정 또는 AI 자율]
- 등장 예정 화수: ep.[번호]
- RELATION.md의 기존 멤버와 몸매 계열 / 표면 성격 / 시안 앞 반응이 겹치지 않도록 설계
```

## 에피소드 워크플로우

### 파일 저장 규칙

```
성인씬 없는 화: episodes/ep.[번호].md
성인씬 있는 화: episodes/ep.[번호]_a.md
```

- 파일명 뒤 `_a`로 성인씬 포함 여부 구분
- 상태 업데이트는 5화 단위로 일괄 처리 (STEP 3)

-----

### STEP 1 — 개요 작성

**첨부 파일**

```
- HISTORY.md
- RELATION.md
```

**프롬프트 (복붙용)**

```
첨부:
- HISTORY.md
- RELATION.md

흐름을 바탕으로 다음 ep.[번호] 개요를 작성해줘

출력 형식:
- 루프 / 연도·계절
- 장소
- 등장 멤버
- 장면 요약 (3~5줄)
- 성인씬 예상 위치 (있을 경우)
- 복선 또는 관계 변화 포인트
```

-----

### STEP 2 — 시나리오 작성

**첨부 파일**

```
- 시안.md
- [등장 캐릭터 이름].md  (메인 등장 인물만, 최대 2~3개)
```

**프롬프트 (복붙용)**

```
첨부:
- 시안.md
- [등장 캐릭터 이름].md

에피소드 정보:
- 루프: [ ]
- 연도/계절: [ ]
- 장소: [ ]
- 등장 멤버: [ ]
- 에피소드 번호: ep.[ ]
- 장면 요약: [ ]

작성 규칙:
1. 캐릭터 성격은 [고정] 영역 기준 유지
2. 시안은 항상 주도권 유지
3. 대화 흐름 자연스럽게, 감정은 서술로 표현
4. 2인 이상 대화 시 [이름] 명시
5. 호칭은 캐릭터 파일 현재 호칭 기준 — 감정적 전환점에서 AI 자율 변경 가능, 변경 시 [수정] 기록
6. 그 외 인물 대사는 태그 없이 서술
7. 성인씬 트리거 조건 도달 시 → 구역 포맷만 삽입, 묘사 없음, <progress> 태그만 기재
8. 시나리오 완성 후 업데이트 출력 없음 — 별도 요청 처리
9. 모든 출력은 반드시 한국어로 작성

문체 기준:
- 단문으로 끊지 않고 호흡이 긴 문장 위주로 작성
- 심리와 감정은 직접 서술하지 않고 행동과 신체 반응으로 간접 표현
- 행동 → 신체 반응 → 감각 순서로 층위를 쌓아 묘사
- 후각 / 촉각 / 청각 등 감각 디테일을 구체적 단어로 표현
- 템포 전환이 필요할 때만 짧은 한 줄 문장 사용
- 인물의 의지와 본능이 충돌하는 방식으로 반응 묘사

분량 기준:
- 성인씬 있는 화: 2,000~3,000자 (씬에 집중)
- 성인씬 없는 화: 4,000~5,000자
  - 단순히 텍스트를 늘리지 않음
  - 관계 변화 / 복선 / 감정 누적 / 사건 전진이 실질적으로 이루어져야 함
  - 화가 끝날 때 이전과 달라진 것이 반드시 하나 이상 있어야 함
```

-----

### STEP 3 — 기록 업데이트

**첨부 파일**

```
- 완성된 ep.[번호] 원고 5편 (_a 파일은 성인씬 포함 화)
- [등장 캐릭터 이름].md
- RELATION.md
- HISTORY.md
```

**프롬프트 (복붙용)**

```
첨부:
- ep.[번호]~ep.[번호] 완성 원고 5편 (_a 파일은 성인씬 포함 화)
- [등장 캐릭터 이름].md
- RELATION.md
- HISTORY.md

5화 묶음 원고 기준으로 아래 항목 업데이트 출력해줘:

1. [캐릭터].md [수정] 항목: 변경 전 → 변경 후
2. RELATION.md 변동: 내용
3. HISTORY.md 추가: ep.번호 / 한줄 요약 / 성인씬 번호 (#번호 또는 -)
4. 관계 진도 변동 반영
5. 모든 출력은 반드시 한국어로 작성
```

> STEP 3 완료 후 아래 5화 점검 프롬프트 이어서 실행

**5화 점검 프롬프트 (복붙용)**

```
첨부:
- HISTORY.md
- RELATION.md

ep.[번호] 기준 점검 요청
점검 항목:
1. 캐릭터 성격 일관성 유지 여부
2. 하렘 내부 관계 변화 요약
3. 복선 트래커 점검 (회수 예정 복선 확인)
4. 다음 5화 복선/이벤트 제안
5. 메인 → 서브 이동 예정 멤버 여부
6. 서브 → 메인 승격 검토
7. 새 서브 멤버 투입 시점 제안
```

## 루프 전환

**첨부 파일**

```
- 시안.md
- HISTORY.md
- RELATION.md
```

1. HISTORY.md 상단에 직전 루프 최종 상태 요약 추가
1. RELATION.md 시안 현재 상태 갱신
1. RELATION.md 하렘 현황 초기화
1. RELATION.md 관계망 초기화 / 복선 트래커 완료 처리
1. 각 캐릭터 파일 [수정] 영역 초기화
1. 각 캐릭터 파일 [가변] 영역 갱신
