# 워크플로우

## 세션 진행 규칙

### 화수 지정 공통 규칙

- `"소설 5화 시작해줘"`, `"소설 10화 시작해줘"`, `"소설 20화 시작해줘"`처럼 **5화 이상 화수를 함께 지정한 요청**은 모두 처리 대상에 포함한다
- `"소설 5화 자동으로 시작해줘"`, `"소설 10화 자동으로 시작해줘"`, `"소설 20화 자동으로 시작해줘"`, `"소설 50화 자동으로 시작해줘"`처럼 **자동 진행 + 화수 지정 요청**도 동일하게 처리한다
- 화수 지정 요청은 **5의 배수만 허용**한다. 해석 방식: `요청 화수 ÷ 5 = 세션 반복 횟수`
- 따라서 10화 요청은 5화 세션 2회, 20화 요청은 5화 세션 4회, 50화 요청은 5화 세션 10회 연속으로 처리한다
- 각 5화 세션이 끝날 때마다 STEP 3 → STEP 4 → 5화 점검까지 완료한 뒤 다음 5화 세션으로 넘어간다
- 화수 지정 요청이 50화 이상이어서 완료 시점의 누적 완성 화수가 50의 배수가 되면, 마지막 5화 세션 종료 직후 `setting/연대기압축규칙.md`를 적용한다
- 사용자가 화수를 지정하지 않으면 기본값은 다음 5화 1세션이다

### "소설 시작해줘"

- 아래 순서로 **다음 5화 단위 세션**을 시작한다
- STEP 1 — 다음 5화 개요안 작성
  - 상세 규칙: `setting/개요작성규칙.md`
  - 최소 2개 이상의 개요안을 제시하고, 각 안의 핵심 갈등/관계 변화/돌발 이벤트 방향 차이를 짧게 함께 적는다
  - 사용자에게 개요안 선택 또는 수정 의견을 확인받은 뒤 다음 단계로 진행한다
- STEP 2 × 5 — 확정된 개요 순서대로 5화 시나리오 작성 및 `episodes/` 파일 저장
  - 상세 규칙: `setting/시나리오작성규칙.md`
- STEP 3 — 캐릭터 파일 [가변] 항목 / `관계망.md` / `연대기.md` 일괄 업데이트
  - 상세 규칙: `setting/기록업데이트규칙.md`
- STEP 4 — HTML 변환 실행 → Git 커밋·푸시
  - 상세 규칙: `setting/기록업데이트규칙.md`
- 5화 점검
  - 상세 규칙: `setting/기록업데이트규칙.md`
- 다음 5화를 이어서 진행할 때도 동일하게 STEP 1에서 개요안을 다시 제시하고 확인받는다
- 화수를 함께 지정한 경우에는 위 5화 세션을 요청 화수만큼 반복한다

### "소설 자동으로 시작해줘"

- 아래 순서로 **다음 5화 단위 세션**을 자동 처리한다
- STEP 1 — 다음 5화 개요안 작성 및 내부 선택
  - 상세 규칙: `setting/개요작성규칙.md`
  - 최소 2개 이상의 개요안을 먼저 구상한 뒤, 현재 관계선/복선/연대기 흐름에 가장 적합한 안을 1개 선정한다
  - 사용자 확인 없이 선정한 안으로 바로 다음 단계로 진행한다
- STEP 2 × 5 — 선정한 개요 순서대로 5화 시나리오 작성 및 `episodes/` 파일 저장
  - 상세 규칙: `setting/시나리오작성규칙.md`
- STEP 3 — 캐릭터 파일 [가변] 항목 / `관계망.md` / `연대기.md` 일괄 업데이트
  - 상세 규칙: `setting/기록업데이트규칙.md`
- STEP 4 — HTML 변환 실행 → Git 커밋·푸시
  - 상세 규칙: `setting/기록업데이트규칙.md`
- 5화 점검
  - 상세 규칙: `setting/기록업데이트규칙.md`
- 다음 5화를 이어서 진행할 때도 동일하게 STEP 1에서 복수 개요안을 구상한 뒤 최적안을 내부 선택해 계속 진행한다
- 화수를 함께 지정한 경우에는 위 5화 세션을 요청 화수만큼 반복한다

## 신규 캐릭터 규칙

- **김시안 취업 확정 전까지 신규 주요 여성 캐릭터 추가 금지** — 자동 판정, 20화 경과 규칙, 생활권 전환 이벤트보다 우선한다
- 하렘에 새 캐릭터가 필요한 경우, 반드시 `캐릭터양식.md` 기준으로 파일을 먼저 생성한 뒤 등장시킨다
- 파일 없이 이름만 임의로 사용하는 것은 금지
- STEP 1 개요 단계에서 신규 캐릭터 투입이 결정되면, 개요 출력 후 시나리오 작성 전에 캐릭터 파일을 자동 생성하고 작업을 계속한다
- 생성 시 `관계망.md`의 기존 멤버와 몸매 계열 / 표면 성격 / 김시안 앞 반응이 겹치지 않도록 설계
- **나이 설정**: 관계망.md의 현재 연도 기준 연나이로 설계한다. 생년도 공식: `생년도 = 현재 연도 - 목표 연나이 + 1` — 예) 2014년에 20세 = 1995년생. 세계관 연령 제한(20~25세)도 연나이 기준으로 적용한다
- 신규 캐릭터는 첫 등장부터 하렘 멤버로 확정하지 않고 서브 후보로 시작하며, 기존 관계에 어떤 새로운 역할과 갈등을 만드는지가 장면 안에서 드러나야 한다

### 하렘 구성 판정

- STEP 1을 시작할 때마다 관계망.md와 연대기.md를 기준으로 아래 항목을 모두 판정한다
  - 기존 메인 멤버: 메인 유지 / 서브 이동 검토
  - 기존 서브 멤버: 서브 유지 / 메인 승격 검토
  - 신규 캐릭터: 투입 / 보류 (`김시안 현재 상태`가 취업 전이면 무조건 보류)
- 메인 → 서브 이동은 커리어, 유학, 장기 부재, 개인적 사정, 심리적 거리감처럼 관계의 중심성이 실제로 낮아지는 흐름이 누적될 때만 적용한다
- 신규 캐릭터 투입이나 메인 정원 확보만을 이유로 기존 메인을 임의로 서브로 이동시키지 않는다
- 서브 → 메인 승격은 친밀도나 관계 진도만으로 결정하지 않는다. 반복적인 선택, 위기에서의 재접근, 기존 멤버와의 관계 정립, 시안의 생활에서 맡는 중심 역할이 확인되어야 한다
- 승격·이동 후보가 있으면 다음 5화 개요에 이를 확정하거나 시험하는 사건을 최소 1개 포함하고, 변화가 확정되면 STEP 3에서 캐릭터 파일과 관계망.md에 반영한다
- 신규 캐릭터 판정을 위해 연대기.md에서 마지막 신규 주요 여성의 첫 등장 화수를 확인한다
- 아래 조건 중 하나라도 해당하면 다음 5화 안에 신규 캐릭터 투입을 우선 검토한다
  - 기존 멤버들의 관계가 합의·공존 등 안정 국면에 진입해 같은 갈등이나 관계 확인이 반복될 가능성이 높음
  - 계절, 방학, 졸업, 취업, 여행, 이사 등 생활권 전환으로 새로운 만남을 만들 자연스러운 사건이 발생함
  - 활성 주요 여성 캐릭터가 2명 이하라 관계 구도가 장기간 고정됨
- 마지막 신규 주요 여성의 첫 등장 후 **20화 이상** 지났다면, 하렘 정원 초과나 명확한 서사적 불가능 사유가 없는 한 다음 5화 안에 신규 서브 후보를 반드시 등장시킨다
- 단, 김시안 취업 확정 전 구간에서는 위 신규 캐릭터 투입 검토와 20화 경과 의무를 모두 보류하고, 취업 확정 직후 다음 5화부터 다시 재개한다
- 연간 기본 등장 상한을 넘기는 경우에는 여행, 직장, 소개, 우연한 재회 등 사건 기반의 추가 등장으로 설계하고 개요에 그 근거를 명시한다
- 단순 인원 보충은 금지한다. 기존 멤버와 역할 / 성격 / 생활권 / 시안과의 관계 패턴 중 최소 2개 이상이 달라야 한다

## 에피소드 워크플로우

### 파일 저장 규칙

- 1단계(스킨십)만 있는 화: `episodes/ep.[번호].md` — 본문 직접 묘사, 성인씬 구역 불필요
- 2단계 이상 성인씬 있는 화: `episodes/ep.[번호]_a.md` — **같은 번호의 일반 파일 생성 금지**
- 상태 업데이트는 5화 단위로 일괄 처리 (STEP 3)
- **이전 에피소드 파일 읽기 금지** — 직전 화 포함 모든 episodes/ 파일 열람 불가. 맥락은 연대기.md로만 파악

### 돌발 이벤트 규칙

- 5화마다 최소 1회 발생
- 아래 세 유형 중 상황에 가장 적합한 것을 선택하며, 동일 유형의 연속 반복은 피한다

| 유형 | 설명 |
|------|------|
| 약한 변화 | 분위기·관계 온도의 소규모 전환 |
| 관계 전환 | 멤버 간 역학 변화 / 새 인물 개입 / 호칭·거리감 변화 |
| 중대한 위기 | 서사 방향을 바꾸는 갈등·사건·이별 위기 |

- 이벤트는 서사 방향이나 인물 관계에 실질적인 영향을 남겨야 한다
- 발생 이벤트 유형은 STEP 3 업데이트 시 연대기.md에 기록
